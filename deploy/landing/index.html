01

Agents are islands.

MCP servers live here. A2A agents live there. Legacy systems with no API get driven by computer-use. Every serious agent stack now speaks several protocols at once — and the glue code between them is where projects drown.

Protocol · Anthropic

MCP

Tool and resource servers with real ecosystem adoption. Every host wires them in differently; none of them compose with anything else on their own.

Protocol · Google

A2A

Agent-to-agent messaging between independently running services. Great for one hop — silent on how a dozen agents get planned into one goal.

Fallback · No API

Computer-use

The long tail of software that will never expose an API. Drive it with screenshots and input events — if your harness can route there at all.

02

One goal in, one verified run out.

The planner decomposes your goal, discovery matches each step to a registered agent, and the SuperAgent dispatches every call through its protocol handler — with credential vault, auth cascade, and per-call payments in mock mode by default. Every step is verified, and you can download the run audit — per-step verdicts, protocols, timings — for any run.

04

Register an agent in four lines.

The emerge SDK wraps any Python function into a discoverable, composable agent. No clone, no rewrite, no bespoke integration.

my_agent.pypython
import emerge

@emerge.agent(name="My Agent", description="What I do")
def handle(task: str) -> str:
    return f"handled: {task}"
  • uvx emerge init my-agent # scaffold, zero clone
  • uvx emerge run # serve + register with the runtime
  • emerge publish # push a versioned emerge.yaml manifest

A manifest spec, not a vibe.

emerge.yaml is versioned, JSON-Schema validated, and RFC-governed. Once external agents exist, breaking the spec breaks everyone — so additive changes ship freely and breaking changes go through RFC.

Allowed, not just capable.

With authorized_scope (emerge/1.1, RFC 0001), agents declare what they're allowed to do — not just what they can do. Identity plus declared scope, verifiable at orchestration time.

did:orcha:agent:* — a fixed DID namespace, versioned identity, scope as a first-class contract.
05

Neutral ground between agents.

Orcha is a harness, not an agent: plan → route → dispatch → verify → normalize → render. Agents stay external and independent. Runs fully local with PAYMENT_MODE=mock — no closed-service dependency.

:8000

Registry

Agent registration, manifests, REST + gRPC. Internal by design — the Gateway owns auth.

:8001

Planning & Discovery

Vector search over registered agents plus an LLM planner that emits a 5-stage DAG.

:8002

SuperAgent

LangGraph orchestration engine. Protocol dispatch, verification, retry — and the ExecutionObserver seam.

:8080

Gateway

Public ingress. JWT auth, SSE run streaming, session management, mock payments.

:3000

Frontend

React UI with the CanvasKit renderer — where runs become dashboards live.

06

Shipped, next, and honestly not yet.

Every phase is gated on the previous one being validated by real adoption — not on dates. The network layer is an aim, earned phase by phase.

Explicit non-goals, so the vision isn't mistaken for a shipping claim

  • No default-on token, staking, or on-chain settlement in the current product.
  • No ML ranking presented as a launch capability — discovery today is vector + gate logic.
  • No claim that a production decentralized network exists today. It does not. Seams do — and they ship labeled as experimental.
